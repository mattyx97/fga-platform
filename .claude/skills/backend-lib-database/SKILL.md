# Backend Lib: Database (Drizzle ORM + PostgreSQL)

This project uses Drizzle ORM with **Relational Queries v2** and centralized `defineRelations()`. Check `package.json` for the currently installed version before assuming an API surface — Drizzle's API has shifted across recent releases.

References:
- [RQB v2 docs](https://orm.drizzle.team/docs/rqb-v2)
- [Relations v1 → v2 migration](https://orm.drizzle.team/docs/relations-v1-v2)
- [Relations v2 Performance](https://orm.drizzle.team/docs/relations-v2#performance)

## Where things live

- **Setup**: `server/lib/database/index.ts` — `setupDatabase()` returning the Drizzle instance
- **Use**: `server/utils/database.ts` → `useDatabase()` (lazy, cached)
- **Schema**: `server/lib/database/schema/` — one file per logical group, barrel-exported from `index.ts`
- **Relations**: defined centrally inside `server/lib/database/schema/index.ts` via `defineRelations(schema, r => ({...}))`
- **Migrations**: `server/lib/database/migrations/` — generated by Drizzle Kit, auto-applied on server startup by a Nitro plugin under `server/plugins/`

## Rules

- **Declare tables with `snakeCase.table`, not `pgTable`** — Drizzle 1.0 dropped the runtime/kit-level `casing` option, and the default is no transformation (TS field name = DB column name verbatim). The project's convention is snake_case column names, so import `snakeCase` from `drizzle-orm/pg-core` and use `snakeCase.table(...)`. The same namespaced object exposes `snakeCase.view`, `snakeCase.materializedView`, `snakeCase.schema` for the rare cases you need them.
- **Use `db.query.*` for reads, not `db.select()`** — RQB v2 understands the relations graph; `db.select()` forces hand-built joins. Fall back to `db.select()` only when RQB can't express what you need (rare).
- **Every FK column needs an `index()`** — without one, relational queries do full table scans (the single biggest perf footgun in RQB v2). Junction tables: one index per FK column **plus** a composite for the primary lookup direction (typically 2 FKs → 3 indexes).
- **Use `pgEnum` for fixed-value columns**, not `text()` — pushes validation down to the DB so invalid values can't slip in via raw SQL or migrations from another service.
- **Inside a transaction, always use `tx`, never `db`** — queries on `db` run outside the transaction and silently break atomicity.
- **If you need UUID IDs use UUIDv7, generated DB-side**: `id: t.uuid().primaryKey().default(sql\`uuidv7()\`)`.

## Querying: db.query

```typescript
const db = useDatabase()

await db.insert(schema.users).values({ id: '123', name: 'John' })

const users = await db.query.users.findMany({ where: { id: '123' } })

const userWithPosts = await db.query.users.findFirst({
  where: { id: '123' },
  with: { posts: { where: { createdAt: { lt: new Date() } } } },
})
```

## Adding a new table

Schema is split into logical files under `server/lib/database/schema/`. To add a new table:

1. Create schema file: `server/lib/database/schema/posts.ts`
2. Import it in `server/lib/database/schema/index.ts` with namespace syntax: `import * as posts from './posts'`
3. Spread it into the existing `schema` object so existing groups stay registered: `export const schema = { ...auth, ...posts }`
4. Add relations for the new table in the `defineRelations()` call in the same `index.ts`

```typescript
// server/lib/database/schema/index.ts
import { defineRelations } from 'drizzle-orm'
import * as auth from './auth'
import * as posts from './posts'

export const schema = { ...auth, ...posts }

export const relations = defineRelations(schema, r => ({
  users: {
    sessions: r.many.betterAuthSession(),
    accounts: r.many.betterAuthAccount(),
    posts: r.many.posts(),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
}))
```

Remember the FK index rule — every FK column gets an `index()`:

```typescript
import { index, snakeCase } from 'drizzle-orm/pg-core'
import { sql } from 'drizzle-orm/sql/sql'

export const posts = snakeCase.table(
  'posts',
  t => ({
    id: t.uuid().primaryKey().default(sql`uuidv7()`),
    title: t.text().notNull(),
    authorId: t.uuid().notNull().references(() => users.id, { onDelete: 'cascade' }),
  }),
  table => [index().on(table.authorId)],
)
```

## Enums

```typescript
export const roleEnum = pgEnum('role', ['owner', 'admin', 'member'])

export const members = snakeCase.table('members', t => ({
  id: t.uuid().primaryKey().default(sql`uuidv7()`),
  role: roleEnum().notNull().default('member'),
}))
```

## Transactions

```typescript
return db.transaction(async (tx) => {
  await tx.update(schema.members).set({ role: 'member' }).where(...)
  await tx.update(schema.members).set({ role: 'owner' }).where(...)
})

// WRONG: db.insert runs outside the transaction
await db.transaction(async (tx) => {
  await db.insert(schema.posts).values(post) // BUG: uses db, not tx
  await tx.insert(schema.tags).values(tags)
})
```

## Migration commands

| Command | Purpose |
|---|---|
| `pnpm db:generate` | Generate a new migration from schema diffs |
| `pnpm db:migrate` | Apply pending migrations |
| `pnpm db:push` | Push schema directly to DB (dev only — bypasses migrations) |
| `pnpm db:studio` | Open Drizzle Studio |

Migrations auto-apply on server startup via the migrations Nitro plugin under `server/plugins/`, so in dev you usually just run `pnpm db:generate` and restart.
